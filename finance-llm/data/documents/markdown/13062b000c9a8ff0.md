3 Introdução
O sistema MDM (Master Data Management) disponibiliza um conjunto abrangente de APIs RESTful para
consulta, integração e subscrição de dados de referência utilizados em processos administrativos e
operacionais da Administração Pública. Estas APIs foram desenhadas para permitir acesso estruturado,
seguro e eficiente a múltiplas entidades de dados mestres, garantindo consistência e integridade em toda
a arquitetura do sistema.
As entidades abrangidas pelas APIs incluem, entre outras, estruturas territoriais (distritos, municípios,
freguesias, NUTS), categorias funcionais (carreiras, regimes, grupos profissionais), orgânicas
governamentais (níveis, âmbitos, tipos de alteração), bem como as próprias entidades institucionais
(organismos públicos e privados).
Cada API segue uma estrutura uniforme que contempla:
• Autenticação via token Bearer, com controlo de permissões por entidade;

• Filtro avançado de dados, incluindo critérios como datas de vigência, códigos legais,
classificações e atributos específicos;
• Paginação configurável, para otimização da performance em grandes volumes de dados;
• Subscrição para notificações automáticas, permitindo que sistemas externos sejam alertados de
atualizações ou novas inserções;
• Resposta padronizada, com metainformação sobre o sucesso da operação, mensagens de erro,
contagem de registos e dados específicos por entidade.
A arquitetura das APIs também promove a reutilização de componentes, como estruturas de filtro comuns
(CommonSearchParameters), parâmetros de paginação (PaginationOptions) e opções de notificação
(NotificationOptions), assegurando coesão entre os diversos serviços expostos.
Estas APIs destinam-se a ser utilizadas por sistemas externos autorizados que necessitem de consultar,
integrar ou sincronizar dados de referência de forma automatizada, mantendo o alinhamento com os
dados mestres do MDM.
4 Autenticação
O acesso aos serviços é protegido por um mecanismo de autenticação do tipo Bearer Token. O token é
obrigatório e deve ser incluído em todas as requisições no cabeçalho HTTP Authorization.
4.1 Obtenção do Token
O acesso às APIs REST do MDM exige autenticação prévia via token do tipo Bearer, obtido por meio do
serviço ExternalSystem_Authenticate. O sistema externo que consome as APIs deve possuir um par
SystemId / SystemKey previamente registado no MDM, através da funcionalidade de Gestão de
Sistemas.

4.2 Validação de Permissões
Além do token válido, cada serviço exige que o sistema consumidor possua permissão explícita para a
entidade correspondente. As permissões são atribuídas na funcionalidade de gestão de sistemas e perfis
do MDM, sob a forma de roles como descrita no próximo capítulo:
5 Permissões Necessárias
O acesso a cada API depende da posse de permissões específicas associadas à entidade consultada.
Estas permissões são configuradas no backoffice da aplicação e, portanto, o cliente dos serviços deverá
pedir que lhe sejam dadas as permissões necessárias mencionando o nome dos serviços aos quais
necessita de aceder.

9 Gestão de Contratos de Subscrição
Objetivo
Este capítulo descreve como os subscritores podem gerir contratos de subscrição ao receber as
notificações automáticas de inserções ou atualizações de dados das tabelas do MDM. As subscrições
podem ser efetuadas via API ou através do ecrã de configuração do sistema.
O que é um Contrato de Subscrição?
Um contrato de subscrição é um padrão em formato JSON que um subscritor recebe sempre que é
notificado de alterações numa ou mais entidades/tabelas de dados do MDM. Como já relatado as
subscrições são solicitadas via API’s, mas também podem ser feitas pelo ecrã de configuração por um
administrador do MDM. A resposta da API subscrita, apresenta um objeto JSON com a seguinte estrutura:
Campo Descrição
Tabela Nome da entidade/tabela a que o subscritor está associado.
Timestamp Data e hora (formato aaaa-mm-ddTHH:MM:SSZ)) em que houve a inserção/alteração da
tabela.
Formato do Contrato (Exemplo JSON)
{
"Tabela": "Entidades",
"Timestamp": "2025-05-14T12:47:24Z",
}
Com o Timestamp e o nome da entidade (tabela) associada, o subscritor poderá utilizar a API e configurar
os filtros corretamente para a obtenção dos dados.

Exemplo:
CommonSearchParameters": {
"Actives":true,

"EffectiveStartDate_Start":"2014-12-31",

"EffectiveEndDate_Start":"2014-12-31",
"EffectiveEndDate_End":"2014-12-31",

[…]
},
